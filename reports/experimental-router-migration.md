# Experimental router migration

## Result

The app uses Vue Router 5.4.0 and its experimental router. The Vite plugin generates a fixed resolver from page files. There are no calls to `addRoute()` or `removeRoute()`.

The website keeps its existing URLs: `/`, `/upload`, the repository list, PRs, comparisons, and commits. The local build keeps its picker and `/branch`, `/compare`, `/worktree`, and `/commit` pages. It also includes the GitHub pages. The local history base still comes from `document.baseURI`, for standalone and hub mounts.

Page files now connect typed route params to shared view components. `GithubDiffPage.vue` and `LocalDiffPage.vue` still use props. They sit outside the scanned page folders. `App.vue` still keys views by path, so a new source gets a new store, while query changes keep the parent store.

The range parser returns `{ base, head }`. Local parsers return discriminated `LocalPage` objects. The PR parser validates digits and preserves strings, including leading zeros, because the source contract uses a string. Owner, repo, and GitHub commit params keep their string types. Local Git targets remain unrestricted strings inside their objects: local comparisons accept two-dot ranges and single revisions as well as three-dot ranges.

Both generated declaration files are included in `packages/app/tsconfig.json`. They form a shared type map for the two builds. Runtime route trees remain separate. A local route name can therefore typecheck in shared code even though the website resolver does not contain it. Route tests check this boundary.

## Required resources

- [Experimental router](https://router.vuejs.org/experimental/router-resolver.md): router factory, component registration, query arrays, relative navigation, HMR, and `TypesConfig.Router`.
- [Custom param parsers](https://router.vuejs.org/experimental/param-parsers.md): parser getters and setters, validation, file names, regex declarations, and generated types.
- [File-based routing](https://router.vuejs.org/file-based-routing.md): plugin order, generated declarations, and both Volar plugins.

## Extra resources that helped

- The npm registry entry for `vue-router/latest`: confirmed that 5.4.0 contains the plugin and experimental exports. The installed 4.6.4 did not provide this setup.
- `node_modules/vue-router/dist/options-*.d.mts`: documented `root`, per-folder `exclude`, parser discovery, `dts`, and `watch` options.
- `node_modules/vue-router/dist/unplugin-*.mjs`: confirmed that `auto-resolver` calls `createFixedResolver()` and showed how file paths enter the generated type map.
- `node_modules/vue-router/dist/index-*.d.ts` and `vue-router-auto-resolver.d.mts`: clarified matcher and router types for behavior tests.
- `node_modules/vue-router/dist/experimental/index.js`: clarified unmatched-route behavior.
- `node_modules/vue-router/dist/volar/sfc-typed-router.cjs`: explained the root directory requirement for page type inference.
- `.agents/00-goal.md`, `.agents/01-architecture.md`, existing source route tests, local page tests, and commit view tests: defined the app behavior to preserve.
- `agent-browser --help`: supplied the browser commands used for navigation checks.

## Environment and test problems

- The web reader could not open the three Markdown guide URLs. Shell download first failed with `curl: (6) Could not resolve host: router.vuejs.org`. Network-approved `curl` with a browser user-agent downloaded all three guides.
- Guessed extra guide URLs `/experimental/fixed-resolver.md` and `/options.md` returned HTTP 404. The installed package declarations and implementation supplied the missing API details.
- File watching failed with `Error: EMFILE: too many open files, watch`. Polling allowed the dev server to run. Production builds and route tests now disable plugin watching.
- The sandbox first rejected the dev server socket with `listen EPERM: operation not permitted 127.0.0.1:5173`. Running the server with network permission resolved it.
- A local Vitest configuration initially defined `PR_EMBED` as false. Vitest exposed it through the environment as the truthy string `"false"`, which suppressed document titles in web tests. The configuration now omits that flag, as the existing web test configuration already did. The title tests then passed.
- The broad workspace test run encountered Git signing errors in temporary-repository tests: `gpg failed to sign the data` and `fatal: failed to write commit object`. CLI agent tests also timed out or failed. These results do not establish a full workspace pass.
- Locale parity tests fail for all 11 translated locales because `review.ownPrCommentOnly` is missing. The same 11 failures occur with the original test configuration. Locale files were not changed.
- Builds retain warnings about large chunks, extensionless Vite config imports, browser externalization of `node:fs`, and `import.meta` in the embed IIFE. The builds complete.

## Validation

- All 30 routing behavior tests pass. They use the actual generated fixed resolvers for the website and local build where applicable.
- App type checking, lint on changed source/configuration files and this report, and `git diff --check` pass.
- Tests cover source round trips, rich named params, numeric PR validation, invalid compare ranges, exclusion of local routes from the website, branch slashes, `%`, `#`, local revision formats, worktree routes, page remounts, commit query arrays, query/hash preservation, and back navigation.
- Browser checks loaded the landing page, opened the upload modal, loaded a sample patch at `/upload`, loaded PR #45 with `?from=antfu`, followed its repository link, loaded `main...main`, and loaded a public commit. These checks did not report page errors.
- Web, local, and embed builds were run. The live local RPC server and hub authentication were not exercised in the browser; local route resolution and build output were checked.
- The final full app test run has 217 passing tests and 11 locale failures. The initial full workspace run had 436 passing tests, 38 failures, and one unhandled error; it included the environment and configuration issues described above.
